Verified research from 2023 to 2025 shows AI generated code ships features fast but often carries security flaws without review. Formal verification of 331000 C programs reports at least 62.07 percent vulnerable as of 2024, Python benchmarks focused on security report over 75 percent insecure as of 2024, while real world GitHub analysis finds 27.3 percent of 733 AI snippets with weaknesses as of 2023 to 2024. Verification closes the gap.

## Controlled studies set the upper bound

Controlled studies use neutral zero shot prompts and formal methods to label flaws. They measure what models do without project context or reviewers.

FormAI at PROMISE 2023 published 112000 C programs generated by GPT 3.5 turbo with dynamic prompting. Using ESBMC formal checker, authors classify at least 51.24 percent vulnerable as of 2023, see [FormAI at PROMISE 2023](https://dl.acm.org/doi/10.1007/s10664-024-10590-1). ESBMC provides counterexamples that reduce false positives.

FormAI v2 expands to nine models including GPT 4o mini, Gemini Pro 1.0, Falcon 180B and Code Llama 13B with 331000 compilable C programs as of 2024. Each program is labeled through unbounded verification. The study reports at least 62.07 percent vulnerable with similar patterns and 42 CWE types including six in MITRE Top 25 2023, see [FormAI v2](https://arxiv.org/html/2404.18353v2). This figure is a lower bound under that method, not a worst case estimate.

Security focused benchmarks raise rates when tasks target risky code. A study of four models across 67 CWE types on SecurityEval reports 76.2 percent insecure on average and over 75 percent vulnerable as of 2024, see [the SecurityEval study](https://arxiv.org/html/2408.10495v1). Georgetown CSET tests five LLMs with prompts likely to elicit Top 25 patterns and reports about 48 percent compilable but buggy and about 30 percent verified secure as of 2023, see [Georgetown CSET](https://cset.georgetown.edu/wp-content/uploads/CSET-Cybersecurity-Risks-of-AI-Generated-Code.pdf). It also summarizes earlier results such as Pearce et al 2021 reporting about 40 percent of 1689 Copilot programs vulnerable to the MITRE 2021 Top 25.

## Real world data sets the lower bound

Real world studies collect code that already passed some review and tooling, so rates are lower but still material.

A study of 733 AI generated snippets from GitHub projects using Copilot and similar tools reports 27.3 percent contain at least one security weakness as of 2023 to 2024 [https://arxiv.org/html/2310.02059v3]. Python shows 29.5 percent with weaknesses and JavaScript shows 24.2 percent in that sample. Those 200 vulnerable snippets contain 628 weaknesses across 43 CWE types, average 3 per vulnerable snippet and up to 22 in a 1595 line file. Eight map to the 2023 Top 25 including CWE 330 insufficiently random values, CWE 94 code injection, CWE 79 cross site scripting and CWE 78 OS command injection.

A 2025 analysis of 7703 files attributed to AI tools reports 4241 CWE instances across 77 types using CodeQL [https://link.springer.com/chapter/10.1007/978-981-95-3537-8_9]. It reports 87.9 percent with no CWE mapped flaw, leaving a remainder. As of 2025 language split is Python 16.18 to 18.50 percent, JavaScript 8.66 to 8.99 percent, TypeScript 2.50 to 7.14 percent [https://link.springer.com/chapter/10.1007/978-981-95-3537-8_9]. Copilot shows better density for Python at 1739 lines per CWE while ChatGPT shows better for JavaScript and about 39 percent are AI generated docs.

These two views show where context helps. Zero shot isolated tasks raise rates, while reviewed code with standards lowers them without eliminating repeated CWEs tied to randomness, injection, XSS and resource cleanup.

## Language effects and repair signals

A 2025 multi language study evaluates 200 tasks across Python, Java, C++ and C with five LLM families. It checks syntax, correctness with 4000 tests per program and security with SonarQube and CodeQL plus manual review as of 2025 [https://arxiv.org/html/2502.01853v2]. Python and Java achieve higher correctness and fewer findings than C and C++ where memory safety, secrets and crypto misuse are more common. Many models fail to use modern features such as Java 17 APIs and outdated methods remain common in C++.

A study of 108 Java questions compares StackOverflow and ChatGPT. Using CodeQL it reports 248 flaws in ChatGPT versus 302 in StackOverflow, 20 percent fewer with 25 percent overlap as of 2024 [https://arxiv.org/html/2403.15600v1]. ChatGPT shows 19 CWE types versus 22 in StackOverflow in that sample. Both human and AI sources propagate insecure patterns without verification.

Repair data shows tooling plus review beats single shot fixes. GPT 3.5 and GPT 4 achieve 33.2 percent to 59.6 percent repairing insecure code from four LLMs, but fix their own code less often, indicating blind spots as of 2024 [https://arxiv.org/html/2408.10495v1]. With iterative feedback assisted by semantic engines, success rises to 65.9 percent to 85.5 percent as of 2024 [https://arxiv.org/html/2408.10495v1]. Detection false positives are higher for LLMs. GPT 3.5 reports 4.3 percent and GPT 4 reports 3.1 percent versus CodeQL and Bandit below 1 percent as of 2024 [https://arxiv.org/html/2408.10495v1]. In the GitHub 733 study, basic fix command resolves 19.3 percent of weaknesses while an enhanced prompt with the warning resolves 55.5 percent as of 2023 to 2024 [https://arxiv.org/html/2310.02059v3].

## What this means for release assurance

Treat AI output as untrusted input to the rest of your system. OWASP Top 10 for LLM Applications 2025 defines LLM05 Improper Output Handling as insufficient validation of model outputs before they reach browsers, shells, SQL or other agents, see [the OWASP Top 10 for LLM Applications project](https://owasp.org/www-project-top-10-for-large-language-model-applications/). The companion Gen AI page lists XSS, SQL injection and SSRF as downstream effects when handling is missing as of April 2024, see [OWASP Gen AI LLM05](https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/). GitHub agentic principles as of November 2025 recommend visible context, firewalling, limiting sensitive access, preventing irreversible changes and clear attribution [https://github.blog/ai-and-ml/github-copilot/how-githubs-agentic-security-principles-make-our-ai-agents-as-secure-as-possible/].

Isolate risk by language and path. Keep auth, crypto and input handling in memory safe languages with platform secrets and crypto APIs where possible. Where C or C++ is required, prioritize memory safety review because FormAI and the multi language study report highest density there.

Add deterministic checks at release, not only in the IDE. Linters, CodeQL or Semgrep rules, secret scanning and tests for auth boundaries catch repeat offenders seen in the datasets. Keep fixes as proposals requiring review, not silent automatic rewrites, so humans stay in the loop on security changes.

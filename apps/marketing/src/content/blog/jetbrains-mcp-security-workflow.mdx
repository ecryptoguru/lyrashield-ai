JetBrains IDEs with AI Assistant can secure AI built apps by adding LyraShield MCP as JSON via Settings to AI Assistant to MCP to Add As JSON using npx -y @lyrashield/mcp with lsk_ key or remote with Bearer auth, then verifying connection and scanning inline for OWASP risks.

JetBrains with AI Assistant changes many files, propagating [OWASP Top 10](https://owasp.org/www-project-top-ten/) issues like SSRF and injection. This guide integrates LyraShield via [vibe coding security guide](/blog/vibe-coding-security-guide) pattern. LyraShield AI is agent native AppSec at [LyraShield site](https://lyrashieldai.com), following Target to Scan to Verified Finding to Fix pull request to Retest to Report. See [JetBrains integration guide](/docs/integrations/jetbrains) and [Replit security checklist](/blog/replit-app-security-checklist). Contract aligns with [Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro) and [GitHub Actions](https://docs.github.com/en/actions).

## 1. Prerequisites and api key setup

Create LyraShield API key starting with lsk_ and store as LYRASHIELD_API_KEY. Never commit key to source control or chat logs. For local work, export it in shell profile. For teams, keep it in secret manager and add to GitHub repository secrets for CI parity. Naming consistency between shell, IDE config and CI reduces misconfig.

You need Node 18 plus so npx resolves pinned package, jetbrains updated to build supporting MCP, and testable target such as http://localhost:3000 or repo root. LyraShield MCP supports stdio via npx -y @lyrashield/mcp and remote HTTP at [remote MCP endpoint](https://app.lyrashieldai.com/api/mcp) using Bearer lsk_ key. Stdio keeps traffic local, remote enables central policy.

Review [CWE Top 25](https://cwe.mitre.org/top25/archive/cwe/top25.html) and [OWASP Top 10](https://owasp.org/www-project-top-ten/) to map checks to weaknesses your team tracks, and [NIST SSDF](https://csrc.nist.gov/projects/ssdf) for secure build. LyraShield v1 is designed to cover agentic pentest plus SCA and secrets with SARIF output. Fix pull requests are proposals requiring review, not hands off merges, after Sprints 0 to 2 shipped MCP contract. Steps are generate key with scan scope, export variable, verify npx works, add secret to GitHub, check Node version. See [JetBrains integration guide](/docs/integrations/jetbrains).


## 2. Configure MCP server in jetbrains config file

jetbrains reads MCP from Settings to AI Assistant to MCP to Add As JSON. Top level key is mcpServers. Include stdio and remote to switch without code edits. Use pinned npx -y @lyrashield/mcp for stdio.

```json
{
  "mcpServers": {
    "lyrashield": {
      "command": "npx",
      "args": ["-y", "@lyrashield/mcp"],
      "env": {
        "LYRASHIELD_API_KEY": "${env:LYRASHIELD_API_KEY}"
      }
    },
    "lyrashield-remote": {
      "url": "https://app.lyrashieldai.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${env:LYRASHIELD_API_KEY}"
      }
    }
  }
}
```

Placeholder `${env:LYRASHIELD_API_KEY}` is resolved securely without writing secret to disk. Remote validates Bearer lsk_ at [remote MCP endpoint](https://app.lyrashieldai.com/api/mcp). Do not commit real values, commit placeholder only and document setup in [JetBrains integration guide](/docs/integrations/jetbrains) onboarding. For multiple projects, keep personal keys in global config and team policy in project file. See [Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro) and [GitHub Actions](https://docs.github.com/en/actions) for parity.


## 3. Verify the connection inside jetbrains

Restart jetbrains after saving config and open MCP servers view to confirm lyrashield shows connected with tools. In chat ask to list MCP tools to see scan tool. This confirms handshake completed.

If disconnected, open log panel. For 401 from [remote MCP endpoint](https://app.lyrashieldai.com/api/mcp) reissue key. For npx not found or EACCES fix Node PATH or install via nvm user space. Run npx -y @lyrashield/mcp manually in terminal with LYRASHIELD_API_KEY set to confirm handshake JSON prints. This isolates IDE versus Node issues.

Verification prevents silent failure where agent assumes scan succeeded but server was unreachable. That leaves [OWASP Top 10](https://owasp.org/www-project-top-ten/) risks undetected and breaks verification loop. Document success in [JetBrains integration guide](/docs/integrations/jetbrains) and allow egress to [remote MCP endpoint](https://app.lyrashieldai.com/api/mcp) if org blocks external.


## 4. Run a security check inline while you code

With MCP connected, prompt agent to scan current target before committing. Example prompt is scan target http://localhost:3000 for injection and secrets using LyraShield and return verified findings only with file paths and CWE.

Agent calls MCP tool and returns file, line, evidence snippet or reproduction notes, and remediation pointers that reference [OWASP Top 10](https://owasp.org/www-project-top-ten/). For injection it shows untrusted input flowing into query without validation. For secrets it shows detected key pattern in source. For supply chain it maps lock entries against [OSV database](https://osv.dev/).

LyraShield is designed to reduce noise by returning verified findings that can be retested via same MCP call. Fix workflow is designed to propose pull request branch that developer reviews, keeping human approval central. Retest loop is key. After fix, ask agent to re run scan on same target and confirm status changed to fixed with evidence. Aligns with [NIST SSDF](https://csrc.nist.gov/projects/ssdf) for verifiable remediation and [CWE Top 25](https://cwe.mitre.org/top25/archive/cwe/top25.html) for classification.

| Check type | What to scan | How to fix |
| --- | --- | --- |
| Injection | API routes concatenating user input into queries | Parameterize queries, validate with schema, enforce allow lists at boundary |
| Secrets | Env example containing real keys, tokens in source | Remove secret, rotate credential, add precommit scan, use secret manager |
| Auth | Missing role check on sensitive routes, permissive CORS | Add auth middleware, test unauthenticated request, set secure cookie flags |
| Supply chain | Vulnerable npm packages with CVE in lockfile | Update lockfile, pin safe version, check [OSV database](https://osv.dev/) advisory, limit scripts |

Use table as prompt template for consistent scans. Reference [Replit security checklist](/blog/replit-app-security-checklist) for deeper checklist.


## 5. Wire the GitHub Action diff aware gate

Local checks improve speed, but team assurance needs CI gate scanning changed files on pull requests and publishing SARIF for triage. LyraShield provides GitHub Action that runs diff aware scan and uploads SARIF. Uses [GitHub Actions](https://docs.github.com/en/actions) and aligns with [OWASP Top 10](https://owasp.org/www-project-top-ten/) pipeline guidance.

```yaml
name: LyraShield Security Gate
on:
  pull_request:
    branches: [main]
jobs:
  security:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
      - name: Run LyraShield diff scan
        uses: lyrashieldai/scan-action@v1
        with:
          api_key: ${{ secrets.LYRASHIELD_API_KEY }}
          target: .
          diff_base: ${{ github.base_ref }}
      - uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: lyrashield-results.sarif
```

Store LYRASHIELD_API_KEY in repository secrets, never in workflow file. Action comments with verified findings and is designed to propose fix branch requiring review on roadmap. SARIF upload lets findings appear in GitHub code scanning alerts. Document secret name in [JetBrains integration guide](/docs/integrations/jetbrains) onboarding and [NIST SSDF](https://csrc.nist.gov/projects/ssdf) for build integrity.


## 6. Add agent rules for continuous guardrails

jetbrains supports project rules that agent reads each task, baking security into definition of done without relying on memory. Add rule forcing LyraShield scan before marking feature complete, covering user input, auth, file upload, secrets or external fetch, and include retest.

Location varies. Cursor uses .cursor/rules/security.mdc with globs, Claude Code uses CLAUDE.md, Windsurf uses .windsurf/rules/security.md, VS Code uses .github/copilot-instructions.md, JetBrains uses .jetbrains/ai-assistant/rules/security.md. Choose location traveling with repo so new clones get same expectation.

```markdown
# Security guardrail
For any task involving user input, auth, file upload or secrets:
1. Call LyraShield MCP scan on target .
2. List verified findings with file and CWE
3. Propose remediation with code edit
4. Ensure .env.example has placeholders only
5. Retest via LyraShield after fix
```

Test rule by scaffolding endpoint accepting query param and confirming scan triggers without reminder. If agent skips, make rule more directive and place file where agent reads on startup. Keep rule short and committed. Pair with [Replit security checklist](/blog/replit-app-security-checklist) and [CWE Top 25](https://cwe.mitre.org/top25/archive/cwe/top25.html) for taxonomy.

The local `.env` **does** carry `MYRA_AZURE_OPENAI_ENDPOINT`/`MYRA_AZURE_OPENAI_API_KEY`, so real LLM answers are possible once `MYRA_GENERATION_ENABLED=1` — confirm the GitHub secret is provisioned and the cost-rate vars (`MYRA_COST_PER_1K_*`) are set (env validation requires them when generation is on).

## Worktree env gotchas (required before any verify in a fresh worktree)

1. `cp .env .worktrees/<wt>/.env` plus `apps/web/.env` and `apps/marketing/.env`.
2. `pnpm install --frozen-lockfile`, then `pnpm --filter @lyrashield/db exec prisma generate`.
3. `pnpm --filter @lyrashield/sdk build` **and** `pnpm --filter @lyrashield/mcp build` — otherwise `web/src/app/api/mcp/route.test.ts` fails to resolve `@lyrashield/mcp` (environmental, not a regression).
4. The web build fails production env validation on a stock `.env` (`MYRA_ALLOWED_EMAILS`, `MYRA_CALENDAR_PROVIDER`, `MYRA_GOOGLE_*`). Build locally with `MYRA_DASHBOARD_ENABLED=0 MYRA_WRITES_ENABLED=0 MYRA_PUBLIC_ENABLED=1 MYRA_PROVIDER=mock MYRA_CALENDAR_PROVIDER=mock` and the Cloudflare test Turnstile pair (`1x00000000000000000000AA` / `1x0000000000000000000000000000000AA`).
5. Marketing `PUBLIC_*` values are baked at build time from `apps/marketing/.env` (not from wrangler runtime vars); the local CSP in `src/middleware.ts` allows `connect-src https:` only, so a plain-HTTP local app is blocked — patch only the built artifact (`dist/server/virtual_astro_middleware.mjs`, `dist/client/_headers`) when verifying locally, never the source.

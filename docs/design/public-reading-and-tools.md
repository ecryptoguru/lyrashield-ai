# Public reading and tools

Modes: **Read** for guides, documentation and policies; **Operate** for local checks;
**Persuade** for pricing, comparisons and supporting product pages.

Preserve the navy/cyan identity, existing typefaces, themes and evidence boundaries.
The primary task comes before decorative artwork. Articles start with their title,
summary and metadata, then navigation and the authored answer. Existing catalog
artwork remains available after the article body. Featured stories place text before
imagery in DOM order, with a split composition on desktop.

Reading headlines use Bricolage Grotesque, approximately 2.15–4.1rem for articles,
with tracking no tighter than −0.035em. Body copy stays at least 1rem with generous
line height. Documentation prose has a 75ch maximum; code and tables retain wider,
local scroll regions. Enlarged text must wrap without expanding the viewport.

Use the existing semantic theme tokens. Links and controls retain visible keyboard
focus. Disclosures, copy feedback, tool availability and errors remain immediate.
Reduced motion removes spatial effects; no animation framework or artificial scroll
controller is added to reading pages.

Category browsing assigns one primary topic from existing editorial context and
retains all secondary tags. Archives use ordinary linked pagination; search covers
the relevant full collection. Dates use one editorial calendar. Structured data,
canonicals and machine-readable links describe the visible, published content.

Local checks enable controls only after initialization, report the actual reviewed
scope and keep missing proof explicit. Inputs stay local. No clean-looking result
may imply coverage of rejected, skipped or unreadable files.

Responsive blog renditions are generated from approved catalog files into `dist`
during both production and preview builds. Generated media is not committed.
All changes remain subject to localhost review before publication or deployment.

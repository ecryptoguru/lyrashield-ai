## Integration audit and clock defect

Three compatible-looking service groups were experimentally batched. One run failed and another passed; the original separate invocation also reproduced the failure. The batch offered roughly one second of potential savings, so the original process isolation remains. Owner/runtime, trial/Myra, FK, team mutations, manifest integrity, preferences and growth-metric invocations retain their distinct roles/databases and existing named-test guards. Metering, webhook and producer reports additionally require every expected case to pass without skips.

The failure exposed an actual initial-due authority mismatch: installed Prisma emitted a client timestamp of `10:23:31.778Z`, while the claim statement's database clock was `10:23:31.777660Z`. A new billing track remained pending because it was 0.34ms in the future. `ensureWebhookTrackRows()` now reads `date_trunc('milliseconds', now())` and supplies the result for both initial due fields. This adds one database read per call, including duplicates; no schema, claim predicate or lease change was needed. Database transaction time is deliberately used so the values also remain valid inside an existing transaction.

A Date-only fake clock advanced to year 2100 deterministically failed the old implementation and passed the fix against real PostgreSQL. The regression verifies claim-once behavior, terminal receipt preservation and unchanged future retry schedules/generation/budget on duplicate initialization. Missing database-clock evidence fails closed. The original separate groups passed 37/37 cases (17 metering, 14 webhook, 6 producer) with no skips in 46.26s; the pre-fix 36-case baseline was 45.83s. The actual approximately 31-second lease-renewal proof remains, so no service speedup is claimed.

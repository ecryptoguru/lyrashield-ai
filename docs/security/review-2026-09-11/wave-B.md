## Needs Verification

1. **Account-deletion actor-attribution query runs without workspace context and silently returns zero rows under strict RLS.**
   - Location: `packages/db/src/account-deletion.ts:145` and `:250` — `prisma.auditLog.findMany({ where: { actorUserId: userId } })`, also consumed by `getAccountDeletionPlan` (line 145).
   - Mechanics verified in code: `AuditLog` is in `WORKSPACE_SCOPED_MODELS`; the query carries no `workspaceId` and runs outside `withWorkspaceRLS`/ALS, so `extension.ts:115-119` passes it through unwrapped; `applyQueryGuards` (`scoping.ts:296-303`) adds nothing without a bound context; `strict_workspace_rls` dropped `auditlog_rls_permissive`, leaving only `auditlog_rls_strict` (`"workspaceId" = app.current_workspace_id()`), which is NULL-false when the GUC is unset → the query deterministically returns `[]`.
   - Consequence when it matters: a user whose only link to a surviving workspace is audit history (e.g. removed member, past contributor) is omitted from `affectedWorkspaceIds`. The retained-workspace anonymization loop (`:414-566`) never visits that workspace, so `AuditLog.actorUserId` and all other user-attribution columns (`Scan.createdById`, `Finding.ownerUserId`, `Notification.userId`, etc. — all plain strings, no FK) keep the deleted user's id; no `account.deleted` receipt is appended there; `getAccountDeletionPlan` under-reports `retained` to whoever previews the plan.
   - Reachability unresolved: `DELETE /api/account` fails closed (`ACCOUNT_DELETION_REVIEW_REQUIRED`, `apps/web/src/app/api/account/route.ts:14-18`); the only non-test caller is the operator drill `verify-queue-orphan-fixture.ts:414-416`, which asserts `retained.length === 0` so the defect cannot manifest there. If the support-operated deletion path invokes `deleteUserAccount` for a user with orphan audit attribution, erasure is incomplete (pseudonymous residual, not cross-tenant exposure). Confirm whether any production/support path calls it, and if so wrap the `actorWorkspaces` read in a system-client or per-user enumeration that does not depend on workspace context.
   - v16 interaction: `9dd01cd3` touched this file for "account-deletion RLS coverage" — confirm on the v16 branch whether this query was changed; on `main` it is exactly as described.

2. **License-family `WITH CHECK` permits `workspaceId IS NULL` writes under any context.**
   - Location: `20260818000005_b_l08_license_rls_null_fix/migration.sql:19,23,27` — `WITH CHECK ("workspaceId" = app.current_workspace_id() OR "workspaceId" IS NULL)` on `License`, `LicenseActivation`, `LicenseKey`.
   - Read side is fixed correctly (NULL rows invisible to workspace contexts); the write side intentionally allows NULL-attribution inserts even with no GUC bound. No plain-client write path to these tables exists on `main` (all writes go through `getSystemPrisma` / SECURITY DEFINER), so this is currently unreachable — flagged only to confirm no future or ungrepped write path relies on it. The plain-client tripwire (`rls-plain-client-scan.test.ts`, v16 `9dd01cd3`/`c68b578e`) scans reads; confirm it also blocks plain-client writes to FORCE-RLS tables outside the scoped model set.

## Verified safe (high-confidence)

- **Model-set parity**: all 34 `WORKSPACE_SCOPED_MODELS` entries have a `workspaceId` column; every schema model carrying `workspaceId` is either in the set or a documented exclusion with compensating control — `ArtifactDeletionTask` (RLS enabled, `REVOKE ALL`, no policy → deny-by-default; access only via narrow SECURITY DEFINER functions that re-check workspace context and evidence ownership), `License`/`LicenseActivation`/`LicenseKey`/`SyncCursor` (own strict FORCE-RLS policies), `WorkspaceMember`/`OnboardingState`/`WebhookEventTrack` (documented cross-workspace/per-user/best-effort-attribution semantics).
- **Soft-delete parity**: all schema `deletedAt` columns are in `SOFT_DELETE_MODELS` except `WebhookEvent`, deliberately excluded to keep the provider-event dedupe ledger visible.
- **RLS coverage table**: every workspace-scoped table and every parent-FK child table (`ScanEvent`, `Evidence`, `ScanResultManifest`, `ScanCoverageReceipt`, `FixProposal`, `PullRequest`, `Ticket`, `ScorecardShare`, `ScorecardEvent`, `LicenseRevocation`, version tables) has `ENABLE` + `FORCE` + a strict or parent-FK policy. The `20260803000003` child-table `DISABLE` was a documented hotfix re-enabled by `20260807000003`; all `*_permissive` policies were dropped by `20260721033000` and `20260903100000` — no-context access fails closed.
- **Account billing boundary**: `20260911000000` permissive account policies are OR-ed with workspace policies; the RESTRICTIVE `*_owner_boundary` policies make non-NULL `accountId` rows invisible to workspace-context queries (attribution never exposes a coworker's ledger); `withAccountRLS` clears the workspace GUC so workspace tables fail closed; entitlement everywhere derives from `resolveAccountBilling(...).effectivePlan` on the account — `workspace.plan` is never consulted; scan sponsor identity comes from persisted `Scan.createdById`, never request input (`usage/meter.ts:124-131`).
- **Metering/settlement**: `recordAgentMinutes` binds workspace + account GUCs in one Serializable tx, dual fixed-order advisory locks, idempotency-key dedupe, P2034 retry only before finalization, P2002 replay fallback, failed scans never billed, 1-hour tick bound. Packs/refund/overage/grants/expiry follow the same account-bound, advisory-locked, idempotent pattern.
- **Extension semantics**: no context → no injection, query falls to Postgres which fails closed; explicit `workspaceId`/`accountId` args bind the matching transaction-local GUC on the same connection; `isDatabaseRLSContextBound()` prevents recursive re-wrapping; `AuditLog.create` is delegated to its dedicated extension; soft deletes remap to updates; bulk writes get a `workspaceId` backstop; `update`/`delete` single-row ops rely on RLS + prior scoped reads.
- **Audit chain**: `client.ts` audit extension requires `workspaceId`, opens its own `baseClient` tx, sets the GUC, takes `pg_advisory_xact_lock(hashtextextended(workspaceId))`, reads predecessor under the lock, enforces monotonic `createdAt`, computes v2 chain hash; `account-deletion.ts` rebuilds retained chains under the same lock before appending the `account.deleted` receipt; no caller nests `auditLog.create` inside another transaction (repo-wide grep: all calls are top-level `prisma.`).
- **Deletion boundaries**: `deleteUserAccount` re-derives the plan under per-workspace membership locks + scan-admission locks inside the tx, rechecks confirmation against the locked plan, anonymizes only rows carrying the target `workspaceId` predicate, enqueues artifact deletion through `app.enqueue_artifact_deletion_task` (SECURITY DEFINER validates context match + evidence-URI ownership), hard-deletes sole-owner workspaces only after purging their audit rows (deliberate erasure choice; `workspace_prevent_hard_delete` trigger documented), scrubs `License.ownerEmail` via system client pre-tx. Boundary defect noted in Needs Verification #1.
- **Platform-admin elevation**: challenge rate-limit tx with dual-key advisory locks; nonce is 32-byte CSPRNG, stored as SHA-256 hash, single-use via atomic `updateMany(consumedAt: null, expiresAt > now)`; full authority revalidation inside the mutation tx (allowlisted email, verified, `PLATFORM_OPERATOR`, TOTP enabled, session match/expiry/fresh-TOTP ≤30 min); `PlatformAdminAudit` written atomically in the same tx.
- **System-client justification**: every `getSystemPrisma()` call site reviewed is a legitimate cross-workspace/pre-auth operation — license key-hash lookup/issue/renew/activation (`licenses/*`, internal-key or key-hash gated), public share-token hash lookup returning only `{id, workspaceId, shareExpiresAt}` then re-scoping via `withWorkspaceRLS` (`report-service.ts:297-317`), `verify_api_key`/`touch_api_key_last_used` SECURITY DEFINER, platform-admin console (behind `requirePlatformAdminIdentity`), webhook fan-out, loop-closure sweep (system client for cross-workspace enumeration, then `withWorkspaceRLS` per workspace), artifact-deletion outbox, operator drills with confirmation phrases.
- **Worker context passing**: workers carry no request ALS; scan jobs bind `withWorkspaceRLS`/account contexts explicitly and validate queued claims against persisted canonical state; `complimentary-grant` is dry-run-default, phrase-gated, refuses to overwrite paying subscriptions, binds `withAccountRLS` for the revoke path; `review-terminal-cost-disposition` re-verifies operator + exact scan state inside a locked tx, deterministic receipt IDs, append-only.
- **Raw SQL**: zero `$queryRawUnsafe`/`$executeRawUnsafe` in non-test code repo-wide; all `set_config` calls use parameterized values with `is_local=true`; identifier interpolation appears only in test scaffolding and migration-side `format()` calls with fixed role names; `slow-query-log` emits duration + model/action only — never query text or bind params.
- **Route surface**: every data-touching API route resolves auth (`requirePermission`/`requireWorkspaceAccess`/`requireAuth`/`getSession`/API-key/OAuth bearer/webhook signature) before tenant queries; public paths (ready, scorecard events, referral capture, report verify, license activate/verify, shared reports) are rate-limited, minimal-payload, and either context-free or capability-token gated. Sync routes additionally require membership + sync credential + monotonic CAS under `withWorkspaceRLS`.

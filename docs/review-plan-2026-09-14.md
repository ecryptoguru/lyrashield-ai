## Standards review

1. **P2 — Acquisition deletion lifecycle.** `packages/db/prisma/schema.prisma:1854` and the new migration create account-linked attribution without a User FK/cascade. `packages/db/src/account-deletion.ts` does not clean it up. Add transactional deletion or a reviewed cascade and test deleting an account with attribution.
2. **P2 — Analytics opt-out bypass.** `apps/web/src/lib/analytics.ts:136` writes the acquisition cookie regardless of DNT/GPC; `apps/web/src/app/onboarding/page.tsx:47` claims it without those checks. Align both with the published privacy policy, including old-cookie handling; update the cookie inventory. Test opt-out on both capture and server claim.
3. **P2 — First-touch and retry semantics.** The acquisition cookie is overwritten on signup revisits, and onboarding clears it even if persistence failed. Preserve the first valid cookie and clear only after a successful/no-op claim. Test campaign A then B and a transient claim failure.
4. **P2 — Readiness false positives.** `apps/worker/src/operations/verify-checkout-readiness.ts:47` omits Razorpay Local, gates Polar credentials only on Cloud admission, and accepts any nonempty canary list. Validate all four modes using shared admission rules; credentials must cover each enabled surface. Production-vs-sandbox mismatch must fail a live-readiness check. Add Local-only, malformed-canary, invalid-mode, and environment-mismatch cases.
5. **P3 — ID convention.** `apps/web/src/lib/account-acquisition.ts:33` inserts a stripped UUID despite the repository's cuid rule. Reuse the established cuid creation path.

The acquisition migration enables and forces account RLS, but mocked unit tests do not prove runtime-role isolation. Require owner, other-account, and missing-context SQL checks before deployment. No concrete cross-account disclosure was established in this review.

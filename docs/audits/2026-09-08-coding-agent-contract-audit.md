## Runtime evidence boundary

The registry labels documentation or package conformance as `COMPATIBLE` or `EXPERIMENTAL`; `NATIVE` and `VERIFIED` require a retained client-runtime receipt with client version and platform.

The six-client desktop acceptance remains separate. Devin, Antigravity, OpenCode, and Hermes have authenticated read receipts, and mutation denial was observed. After the user restarted Codex, Desktop 26.901.51231 exposed all 14 installed LyraShield tools: workspace discovery, target discovery, and Gate v2 readiness returned successfully in the desktop task. The legacy target correctly returned `INSUFFICIENT_EVIDENCE` with `ASSESSMENT_UNAVAILABLE` and `EXPECTED_IDENTITY_REQUIRED`. A developer-report request was denied because the OAuth connection has no write scope; no report was created.

Hermes displayed the exact-input approval prompt, but accepting it returned empty form content. Inspection of the installed `tools/mcp_tool.py` confirmed `ElicitResult(action="accept", content={})`, which omits the required `approve` field. LyraShield rejects this invalid response and its terminal fallback remains unavailable in the desktop host. This is a host form limitation, not a successful approved write.

Claude Desktop 1.46388.4 was checked again after restart: the tested Free account's Code tab still displays “Get Claude Code.” Current [Claude Desktop documentation](https://code.claude.com/docs/en/desktop#shared-configuration) confirms that local Code sessions read `~/.claude.json` and `.mcp.json`, and also load `claude_desktop_config.json` servers. The standalone CLI does not read the latter file. Configuration compatibility does not remove the observed account-entitlement block.

The approval compatibility review found that remote tool schemas did not advertise the `approvalId` required to resume a browser-approved call, and that the remote gate compared the input hash using the stored action name without rejecting a different requested tool. The expiry precheck also accepted the exact expiry instant, unlike the database execution claim. Regressions cover remote schema discovery, cross-tool reuse and exact expiry in pending/approved/executed states, malformed approval IDs, and empty elicitation content. These are code-verification results; deployment and a fresh client schema discovery are separate gates.

Exact-input approved writes, expiry/refresh, revocation, permission loss, and upgrade remain unproven across the full six-client matrix. None of these partial results is promoted to complete desktop acceptance.

The coordinated public artifacts are CLI `0.2.4`, MCP `0.2.5`, Agent Plugin `0.1.24`, and marketplace release `v0.1.24` at marketplace commit `454c60e44304ded2a8f91587fe6ad4f78e0cfe70`.

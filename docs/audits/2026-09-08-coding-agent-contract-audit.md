## Runtime evidence boundary

The registry labels documentation or package conformance as `COMPATIBLE` or `EXPERIMENTAL`; `NATIVE` and `VERIFIED` require a retained client-runtime receipt with client version and platform.

The six-client desktop acceptance remains separate. These receipts establish installability, authenticated reads, restart behavior, and fail-closed mutation behavior only. They do not establish an approved write or the remaining lifecycle cases.

The legacy target correctly returned `INSUFFICIENT_EVIDENCE` with `ASSESSMENT_UNAVAILABLE` and `EXPECTED_IDENTITY_REQUIRED`. Hermes displayed the exact-input approval prompt, but accepting it returned empty form content. Inspection of the installed `tools/mcp_tool.py` confirmed `ElicitResult(action="accept", content={})`, which omits the required `approve` field. LyraShield rejects this invalid response and its terminal fallback remains unavailable in the desktop host. This is a host form limitation, not a successful approved write.

Claude Desktop 1.46388.4 was checked again after restart: the tested Free account's Code tab still displays “Get Claude Code.” Current [Claude Desktop documentation](https://code.claude.com/docs/en/desktop#shared-configuration) confirms that local Code sessions read `~/.claude.json` and `.mcp.json`, and also load `claude_desktop_config.json` servers. The standalone CLI does not read the latter file. Configuration compatibility does not remove the observed account-entitlement block.

The approval compatibility review found that remote tool schemas did not advertise the `approvalId` required to resume a browser-approved call, and that the remote gate compared the input hash using the stored action name without rejecting a different requested tool. The expiry precheck also accepted the exact expiry instant, unlike the database execution claim. Regressions cover remote schema discovery, cross-tool reuse and exact expiry in pending/approved/executed states, malformed approval IDs, and empty elicitation content.

The fix merged in product commit `65a36918cf0831237a672477c71a08bd9d88a144`. Exact-main CI run `34178125053` passed, and production release `34178604512` deployed app revision `lyrashield-app--0000319`, scanner revision `lyrashield-scanner--0000292`, and egress-proxy revision `lyrashield-egress-proxy--0000160` at 100% traffic. A fresh post-deployment Codex Desktop task discovered 14 tools: all five mutating schemas expose optional `approvalId`, and none of the nine read-only schemas exposes it. Workspace, target, and Gate v2 reads passed. One unapproved report request failed closed for missing write scope, and no report was created.

Exact-input approved writes, expiry/refresh, revocation, permission loss, and upgrade remain unproven across the full six-client matrix. None of these partial results is promoted to complete desktop acceptance.

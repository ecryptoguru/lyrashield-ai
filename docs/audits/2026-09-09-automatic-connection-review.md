## Selected permission policy

The founder selected Option 3: all active workspace members receive operational read/write permissions, including Viewer, Auditor, External Pentester and Billing Admin. Shared permission checks and UI permission lists use the same operational set. Administrative privileges, API-key scopes, membership checks, and connection ownership boundaries remain enforced. Existing role names are retained for compatibility; the team UI and guide disclose their operational access.

## Remaining release boundaries

- These changes need PR-head CI, review, coordinated package release/deployment and exact-release client acceptance before they are production claims.
- Existing read-only or limited grants are never silently expanded. A client must reconnect when broader authorization is needed. Legacy hosted nondelegated tokens retain their historical approval contract.
- Coding-agent hosts control their own permission dialogs; LyraShield cannot promise to remove them.
- API-key and local stdio calls currently use REST authorization; they do not inherit the hosted OAuth `AgentOperation` replay guarantee.
- WebMCP `prepare_security_scan` remains an explicitly named form-preparation tool. It does not perform a durable scan. Cancellation fixes do not turn it into a scan execution API.
- Gemini's published read-only tool policy is unchanged. This review does not certify mutations in every registry client.
- No real payment, billable scan, production grant expansion, repository auto-merge, or billing-staging resource creation is part of this local validation.

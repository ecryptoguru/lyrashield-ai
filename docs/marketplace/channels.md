# Distribution channel ledger

Last checked: 2026-10-01. This ledger separates **client compatibility** from **directory status**. A submission, approval, or listing does not prove an integration works in a client. Promote compatibility only from a surface-, version-, OS-, artifact-, and transport-specific runtime receipt; promote a directory state only after public readback.

Use these states for listing work: PREPARATION, READY, SUBMITTED, APPROVED, PUBLISHED, REJECTED, and UNKNOWN. UNKNOWN means no current readback. Treat application dashboards and old PRs as historical until checked again. Do not claim "available in marketplace" without a live public listing URL and version.

The latest public marketplace GitHub release read back on 2026-10-01 is [v0.1.29](https://github.com/ecryptoguru/lyrashield-marketplace/releases/tag/v0.1.29), published 2026-09-25. Public Cline and Kilo submissions still target v0.1.12. A repository branch or local artifact version does not establish an immutable marketplace release.

## Runtime evidence record

For each support claim, retain a sanitized record with: client and surface, exact client version, OS, artifact commit/version/hash, transport, tested capabilities, outcome, and limitations. Record install/upgrade/removal, component discovery after reload, OAuth read-only authorization, workspace selection, and explicit denial cases where relevant. Keep secrets, raw customer evidence, and model costs out of receipts. A failed or missing check stays UNKNOWN, COMPATIBLE, or EXPERIMENTAL; directory state cannot upgrade it.
